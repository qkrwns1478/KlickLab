# 코드 리뷰 지적사항 반영

[05-에이전트_구현_코드_리뷰.md](05-에이전트_구현_코드_리뷰.md)의 10건을 검토해 모두 반영했다. 에이전트 테스트 323건 통과, ruff·`tsc --noEmit` 통과. 실제 스택을 띄워 확인하지는 않았다.

## 반영 내용

| # | 변경 | 파일 |
|---|------|------|
| 1 | 차트 `stepId` → `step_id`. 서버가 `asdict`로 보내는 키에 프론트 타입을 맞췄다(히스토리 포함) | `frontend/src/components/agent/types.ts`, `AnswerChart.tsx` |
| 2 | `started` yield를 try 안으로 옮겨, 그 시점에 연결이 끊겨도 `_finish`가 실행된다 | `agent/app/agent/loop.py` |
| 3 | LLM 클라이언트·Executor를 `app.state.llm`/`executor`에 하나만 만들어 `/agent/ask`와 `/agent/runs`가 공유한다. 종료 시 lifespan이 한 번만 닫는다 | `api/ask.py`, `api/runs.py`, `main.py` |
| 4 | 413으로 대체 공급자를 쓴 경우 세션을 고정하지 않는다. 이번 호출만 로컬로 처리하고 다음 호출은 기본 공급자를 다시 시도한다. 폴백 이벤트는 그대로 나간다(`fallback_active`) | `llm/fallback.py` |
| 5 | 쿨다운 중 공유되던 `LLMError`를 `_with_wait`에서 복사해 `wait_ms`가 실행 간에 섞이지 않게 했다 | `llm/fallback.py` |
| 6 | events 시간 조건 검사를 강화했다. 최상위 AND 조건 중 `events.timestamp`를 컬럼이 없는 값과 비교하는 것만 인정한다. `timestamp = timestamp`, `OR true`, 다른 테이블의 `timestamp`는 거절한다 | `sql/guard.py` |
| 7 | DSN 값을 `'...'`로 감싸고 `\`, `'`를 이스케이프한다 | `config.py` |
| 8 | `RunTotals.difficulty`, 메트릭, 트레이스 태그에 승격된 난이도(`state.budget.difficulty`)를 쓴다 | `loop.py` |
| 9 | 에이전트(8000)와 백엔드 Actuator(9091) 포트를 `127.0.0.1`에 바인딩했다 | `docker-compose.yml` |
| 10 | `_fit`이 `None`을 반환해 모델을 부르지 않은 경우 `forced_calls`를 되돌린다 | `loop.py` |

## 참고

- #4는 리뷰가 제안한 두 방법 중 "413에서는 세션을 고정하지 않는다"를 택했다. 기본 공급자가 413을 계속 내면 호출마다 기본 공급자를 한 번 시도한 뒤 로컬로 넘어간다. 루프의 413 압축 경로(`loop.py`)는 모든 공급자가 413일 때만 실행된다.
- #9로 호스트가 아닌 다른 기기에서 에이전트 `:8000`·백엔드 `:9091`에 직접 접근할 수 없다. 프론트는 nginx를 통해 접근한다.
